### Название задачи:
Передача актуальных депозитных ставок в кол-центры банка и партнёрский кол-центр в рамках MVP открытия депозитов

### Функциональные требования (Use Cases)

| № | Действующие лица или системы | Use Case | Описание |
|---|---|---|---|
| 1 | Оператор кол-центра банка / Система кол-центра | Консультация клиента по ставкам | Оператор получает в своей системе актуальные ставки из АБС для ответа на вопросы клиентов |
| 2 | Система кол-центра банка / АБС | Получение ставок | Система КЦ запрашивает актуальные ставки в АБС через API в режиме реального времени |
| 3 | АБС / Партнёрский кол-центр | Выгрузка ставок в файл | АБС формирует файл (CSV/XLS) с актуальными ставками и передаёт его партнёру через защищённый канал (SFTP/PGP) |
| 4 | Оператор партнёрского кол-центра / Система партнёрского КЦ | Консультация по ставкам | Оператор использует файл со ставками для консультации клиентов по телефону |

---

### Нефункциональные требования

| № | Требование |
|---|---|
| 1 | Доступность данных ставок для КЦ банка — 24/7 |
| 2 | Обновление файла для партнёрского КЦ минимум 1 раз в день |
| 3 | Шифрование каналов передачи данных (TLS для API, PGP/SFTP для файлов) |
| 4 | Минимальное влияние на производительность АБС при выдаче ставок |
| 5 | Использование стека технологий банка (Oracle, PL/SQL, Java, .NET, PostgreSQL) |
| 6 | Логирование всех выгрузок и API-запросов для аудита |
| 7 | Формат файла для партнёра — CSV или XLS, совместимый с их системой |
| 8 | Отказоустойчивость решения в случае сбоя одной из интеграций |

---

### Решение

Контекстная диаграмма (C4 Level 1)  
- Клиенты звонят в кол-центр банка или партнёра.  
- Оператор банка получает ставки из АБС через систему КЦ.  
- Партнёрский КЦ получает файл ставок из АБС через SFTP/PGP.

Диаграмма компонентов (C4 Level 3)  
- В АБС реализуется модуль «Выгрузка ставок» с двумя сценариями:
  - API для системы КЦ (онлайн-запрос)
  - Плановая выгрузка файла для партнёра
- В системе КЦ — модуль отображения ставок.
- Для партнёра — настройка приёма и обновления файла.

Логика выбора технологий  
- Используем Oracle/PL-SQL для минимизации рисков интеграции с АБС.  
- Онлайн-запросы в КЦ банка обеспечат актуальность ставок в момент звонка.  
- Для партнёра выбран обмен файлами из-за отсутствия API.  

---

### Альтернативы

1. Дублировать ставки в отдельной БД  
   Плюсы: разгружает АБС  
   Минусы: нужно обеспечивать синхронизацию

2. Ручная передача файлов партнёру  
   Плюсы: не требует интеграции  
   Минусы: зависимость от человеческого фактора, риск ошибок и задержек

---

### Недостатки, ограничения, риски
- Зависимость от АБС: при сбое в АБС КЦ банка не сможет получать актуальные ставки  
- Возможные задержки в доставке файлов партнёру  
- Риск утечки при неверной настройке SFTP/PGP  
- Дополнительная нагрузка на ИТ-команду и администраторов АБС
